### 2.3 生命周期（统一）

```
① 脚本加载期：只做 IIFE 包裹 + 定义全局对象 + 常量。
   **绝对不能**在这里 new THREE.* / 访问 renderer / 抛异常。
② initScene() 期：Lead 调用 create/install(opts)，返回 handle（可能为 null = 不支持）。
③ animate() 期：Lead 每帧调用 handle.update(dt, ctx)（部分模块不需要就不调）。
④ applyState() 期：Lead 把 /api/state 的 live 快照传给 HUD / 天气。
⑤ resize / TOD 切换 / 开关按钮：Lead 调对应 handle 方法。
⑥ dispose()：切场景/重建机群时释放 GPU 资源（本项目可以只实现空壳）。
```

### 2.4 质量档位（Lead 传入，模块必须遵守）

`app3d.html` 已按 GPU 自动识别三档：`high` / `medium` / `cpu`（软件光栅）。

```js
const QUALITY = {
  high:   { pixelRatio:2.0, shadows:true,  shadowMap:2048, bloom:0.58, particles:9000, trees:2600, rocks:520, ao:true,  cloud:true,  postfx:true  },
  medium: { pixelRatio:1.35,shadows:true,  shadowMap:1024, bloom:0.42, particles:5000, trees:1400, rocks:340, ao:true,  cloud:false, postfx:true  },
  cpu:    { pixelRatio:1.0, shadows:false, shadowMap:512,  bloom:0.0,  particles:2500, trees:500,  rocks:90,  ao:false, cloud:false, postfx:false },
}[TIER];
```

* `cpu` 档：**SSAO 必须自动关闭**；粒子数 ≤1200；地形环数 ≤2；任何新模块不得让 CPU 档崩掉。
* 每模块 `opts.quality` 里给到自己的参数，自己再按档位缩放。

## 3. 通用编码约定（验收会看）

1. **经典脚本 + IIFE**：`(function(){ "use strict"; ... window.UAVXXX = {...}; })();`
   不写 `import/export`（否则 `node --check` 也不认、页面加载直接语法错误）。
2. **不污染全局**：除约定的 `window.UAVXXX` 外，不新增 `window.*`；内部变量全部包在 IIFE 里。
3. **异常安全**：`install/create` 内部的 try/catch 自己兜住，失败返回 `null` 并 `log()` 一行原因；
   **不许抛出来把主场景搞崩**（主场景 30 架机 + 地形已经在跑）。
4. **每帧零分配**：`update()` 里不复用 vector 就别 new（提前建好 `tmpVec` 等）。禁止每帧 `new Geometry/Material`。
5. **共享几何/材质缓存**：30 架无人机 × 每架十几个 Mesh，几何体和材质必须模块级缓存复用
   （`led/cone/rotor-disc` 这些"会换色"的除外）。
6. **中文注释**：注释解释「为什么这么做、对应什么真实现象」，因为这是**教学案例**，代码会被学生读。
7. **自检函数**：每个模块必须提供 `selfTest()`，纯逻辑、不依赖 renderer，返回：
   ```js
   { ok: true, checks: [{ name: "kernel 长度", ok: true, detail: "16" }, ...], stats: {...} }
   ```
   验收会通过无头浏览器 `--eval "JSON.stringify(UAVSSAO.selfTest())"` 抓取。
8. **可观测**：`handle.stats` 暴露 `{verts, tris, drawCalls, particles, ms}` 之类，Lead 会显示在 `?debug=1` 面板。
9. **日志**：`opts.log` 回调（默认 `console.log`），前缀 `[SSAO]` / `[Terrain]` / `[UAV]` / `[HUD]` / `[Weather]`。
   正常路径只打 1~2 行，别刷屏。
10. **UTF-8 无 BOM**；文件末尾留空行。

## 4. 模块契约

### 4.1 `static/ssao.js` —— 真 SSAO 后处理

```js
window.UAVSSAO = {
  version: "1.0.0",
  /** 能力检测：无 WebGL2 / 无浮点渲染目标 / cpu 档 → false */
  capable(opts) -> boolean,
  /**
   * 安装到既有 EffectComposer 上：位置在 RenderPass 之后、UnrealBloomPass 之前。
   * @param {object} opts {
   *   THREE, renderer, scene, camera, composer,
   *   tier: "high"|"medium"|"cpu",
   *   quality: { enabled:true, strength:0.9, radius:0.55, samples:16,
   *              halfRes:true, blur:true, bias:0.02, minViewZ:0.5, maxViewZ:420 },
   *   log: (msg)=>{}
   * }
   * @returns {null | {
   *   pass, enabled, setEnabled(b), setStrength(v), setSize(w,h),
   *   update(dt), stats:{samples, kernelSize, rtFormat, ms}, dispose()
   * }}
   */
  install(opts) -> handle|null,
  selfTest() -> {ok, checks, stats},
};
```

**实现要求（按 three r128 写，不要依赖 examples/jsm 的 SSAOPass）**

1. 自己写一个 `class SSAOPass extends THREE.Pass`，在 `render(renderer, writeBuffer, readBuffer)` 里：
   * **一次**法线+深度预渲染：`scene.overrideMaterial = MeshNormalMaterial`，渲染进内部
     `WebGLRenderTarget`，该 RT 挂 `THREE.DepthTexture`；
     渲完必须 `scene.overrideMaterial = null`（否则主场景全变法线色，最典型的踩坑）。
   * 从 `readBuffer.texture` 取 beauty；用 `tDepth` 反投影得到视空间位置（`gl_FragCoord.z` +
     `cameraNear/Far` + `projectionMatrixInverse`），`tNormal` 取视空间法线。
   * 半球核采样（16~24 个预生成样本，随机旋转 per-pixel），逐点比较深度做遮蔽估计，
     值域映射到 `[0,1]` 的 AO；`depth >= maxViewZ / 天空` 的像素 AO 置 1。
   * `halfRes:true` 时 AO 在 1/2 分辨率算，再在合成 pass 里双线性上采样（显著省 GPU）。
   * 可选双边模糊（1~2 次，分离式或 3x3），去掉采样噪声（半径 × 深度自适应）。
   * 合成：`outColor = beauty.rgb * mix(1.0, ao, strength)`；写 `writeBuffer`。
   * **必须**尊重 `pass.renderToScreen`（composer 会设置），用 `THREE.FullScreenQuad`。
2. `install()` 里 `composer.insertPass(pass, 1)`（RenderPass 固定是 index 0）；
   若 composer 为空或 `quality.enabled=false` → 返回 null。
3. `setSize(w,h)` 重建内部 RT（高/中档 RT 尺寸跟 `renderer.getDrawingBufferSize()` 走）；
   主页面 resize 时会调用。
4. `stats.ms`：用 `performance.now()` 统计 SSAO 这一 pass 的耗时（平滑 20 帧）。
5. **视觉验收标准**（无头截图必须能看出来）：
   * 采坑台阶下沿、树根、机身下方出现**屏幕空间接触阴影**（暗边）；
   * 天空/远景**不能**出现黑斑（深度=远平面要跳过）；
   * 无人机在地面附近飞过时，机身下方地面有随距离变化的小范围暗影；
   * 与泛光共存不闪、不糊；`?ssao=0`（Lead 加的开关）关掉后画面与升级前一致。
6. 性能：high 档 1080p 独立显卡 ≤ 2.5 ms；softwa 渲染不低于 3 fps（本项目已有 SwiftShader 场景）。

**自检页**：`static/_dev_ssao.html`（自己写，见 §5）。至少给出三组对比：
`?mode=off|on|compare`（左右分屏或 3 张连续截图），以及一个"台阶/树根/无人机贴地"的测试场景。

### 4.2 `static/terrain_lod.js` —— 地形 LOD（几何 clipmap + 纹理 clipmap）

```js
window.UAVTerrain = {
  version: "1.0.0",
  capable(opts) -> boolean,
  /**
   * @param {object} opts {
   *   THREE, scene, camera,
   *   field: { H: Float32Array, N: int, M: int },   // 现有高程场（见 app3d.html §2/§2b）
   *   world: { width: 176, depth: 128 },            // 世界尺寸（世界中心 = (0,0)）
   *   tier: "high"|"medium"|"cpu",
   *   quality: { enabled:true, rings:4, baseSpacing:null /*null=按 DEM 格自动算*/,
   *              ringScale:2, skirtDepth:3.0, detailRepeat:[48,12,4,1.5],
   *              anisotropy:4, debugTint:false },
   *   log: (msg)=>{}
   * }
   * @returns {null | {
   *   group,                              // 已 add 到 scene 的 THREE.Group
   *   materials: [MeshStandardMaterial],  // 每环一个，Lead 会往里注入云影 shader
   *   heightAt(x,z) -> number,            // 与 app3d.html 的 terrainH 完全一致的公式
   *   update(camera, dt),                 // 每帧：重定位/吸附/LOD 切换
   *   setEnabled(b), setDebug(b),
   *   stats:{rings, verts, tris, drawCalls, ringSpacing:[...]},
   *   dispose()
   * }}
   */
  create(opts) -> handle|null,
  selfTest() -> {ok, checks, stats},
};
```

**实现要求**

1. **几何 clipmap**：以相机 XZ 为中心、由内向外 4 级同心网格（`ringScale=2` 逐级翻倍间距），
   内环细（间距 ≈ DEM 格 `max(world.width/(N-1), world.depth/(M-1))`）、外环粗；
   * 顶点高度 = 对 `field.H` 做**双线性采样**（与 `terrainH` 同公式），保证和树木/碎石/覆盖热力图/水面不穿模；
   * 中心吸附（snap）到本级网格步长的整数倍，避免相机移动时顶点"游动/闪烁"；
   * 环与环之间加**向下裙边**（skirt），杜绝 LOD 裂缝；
   * 外环必须覆盖整个世界矩形并外扩 ≤5%，**任何相机角度都不许看到地形空洞**。
2. **纹理 clipmap（裁剪贴图）**：
   * 模块内部用 canvas 程序化生成一张 512×512 的岩石/土壤细节纹理（`CanvasTexture`，
     `RepeatWrapping`，各向异性按 `quality.anisotropy`）；
   * 每环一套材质：近环 `repeat` 大（贴图细节清晰）、远环 `repeat` 小并靠 mip 自动糊；
   * 必须保留 `vertexColors: true`（沿用 app3d.html 现在的坡度/高程分带配色：
     ROCK `0x3f6a62`、SOIL `0x2b4f39`、DEEP `0x0a2228`，见 app3d.html 第 674~722 行），
     细节纹理只做**乘性增强**，不要把配色改掉；
   * `MeshStandardMaterial` + `flatShading:false`，兼容 scene.fog / 现有光照 / 阴影。
3. **为更大 DEM 铺路**：所有尺寸都从 `field.N/M`、`world` 推导，**禁止硬编码 384/280/176/128**；
   提供 `static/_dev_terrain.html?nx=1024&nz=768` 压力测试（程序化生成大高程场，证明 LOD 后
   三角形数不随 N 线性爆炸）。`stats.tris` 必须给出；high 档 ≤ 260k，medium ≤ 120k，cpu ≤ 40k。
4. **性能**：`update()` 只在相机移动超过 `spacing/2` 时才重建/重定位，不要每帧重建几何。
   每环一次 draw call（或每环按需合批），总 drawCalls ≤ 8。
5. **兼容**：地形网格**不再**用 `PlaneGeometry(176,128, N-1, M-1)` 整张铺（那是现在"粗糙"的根因）。
   但树木/碎石/覆盖热力图/水面/地面站仍按原坐标摆放，高度查询一律走 `handle.heightAt`。

### 4.3 `static/uav_model.js` —— 无人机模型细化

```js
window.UAVModel = {
  version: "1.0.0",
  /**
   * 创建一架增强版六旋翼/四旋翼（与现有 `makeDrone()` 同尺寸：机身 2.1×0.42×2.1）。
   * @param {object} opts {
   *   THREE, tier:"high"|"medium"|"cpu",
   *   quality: { rotorDisc:true, bladeSeg:3, gimbal:true, gear:true, led:true, cone:true },
   *   log
   * }
   * @returns {THREE.Group}  g.userData = {
   *   // —— 与原 makeDrone() 完全兼容的字段（主循环旧代码可直接用）——
   *   rotors, led, ledMat, cone, coneMat,
   *   // —— 新增 ——
   *   anim(dt, ctx),        // 主循环每帧调用（见下）
   *   gimbal: {yaw, pitch, group},   // 云台两轴 Object3D
   *   gear: [Object3D, ...],         // 起落架铰链组
   *   dispose()
   * }
   */
  create(opts) -> THREE.Group,
  selfTest() -> {ok, checks, stats},
};
```

**`anim(dt, ctx)` 的 ctx 字段（Lead 保证传入）**

```js
{
  t,                      // 累计秒
  phase,                  // "PAD" | "CLIMB" | "TRANSIT" | "SURVEY" | "RETURN" | "LAND"
  spin,                   // 现有转速标度：PAD 9 / LAND|CLIMB 18 / busy 38 / 巡航 27
  busy,                   // 是否有任务在跑
  priority,               // "HIGH" | "LOW" | null
  scanning,               // 是否处于 SURVEY 且正在拍
  health,                 // 链路健康度 0~100
  online,                 // 在线
  bank,                   // 现有滚转角（弧度）
  yawRate,                // 偏航角速度（弧度/秒，供云台稳像用）
  lookTarget,             // 可选 THREE.Vector3：云台应注视的世界坐标（扫描点/地面站/数据链路）
}
```

**实现要求**

1. **桨叶运动模糊**（核心）：4 个旋翼，每个 =
   * 2 片薄桨叶（`BoxGeometry` 细长条，绕轴旋转，低转速时可见）；
   * 1 片**运动模糊盘**（圆盘 + 自定义 `ShaderMaterial` 或程序化 canvas 径向条纹贴图，
     `transparent + AdditiveBlending + depthWrite:false`）：不透明度随 `spin` 平滑上升
     （低转速≈0.06、巡航≈0.45、高负载≈0.62），盘面同时带**旋转条纹相位**（看起来在转）；
   * 高速时桨叶本体透明度下降（0.9→0.25），与模糊盘交叉淡入淡出；
   * 视觉验收：截图里巡航中的桨叶是"半透明圆盘 + 隐约桨影"，不是 4 个实心圆片；
     降落/待机时能看清桨叶。
2. **云台跟随**：机腹二轴云台（yaw + pitch 两级 `Group` + 相机机身 + 镜头），`anim` 里用
   **阻尼跟随**（`lerp` + 角速度限幅）朝 `ctx.lookTarget` 转，带轻微稳像抖动（±0.5°）；
   PAD 时回正朝前下方，SURVEY 时俯视扫描点，TRANSIT 时朝前。角度限幅：pitch ∈ [-85°, +20°]。
3. **起落架收放**：4 条腿（或 2 组 ×2 腿）挂在铰链 `Group` 上，`anim` 按 phase 算目标收放量：
   `PAD/LAND → 1.0（放下）`、`CLIMB → 0.6~0.0`、`TRANSIT/SURVEY/RETURN → 0.0（收起）`，
   0.35 s 缓动（smoothstep）。收放只旋转腿部，机身/机臂高度不动。
4. **性能**：30 架机同时存在。几何/材质必须模块级缓存共享；每架机 Mesh 数 ≤ 18（high），
   cpu 档 ≤ 10（关模糊盘/降段数）。不得每帧 new 材质。
5. **兼容**：`g.userData.rotors/led/ledMat/cone/coneMat` 语义不变（主循环旧代码先跑通，再加 anim）。
   模型朝向惯例与原来一致（+Z 为机头，y 轴向上），缩放仍由外层 `group.scale.setScalar(1.5)` 负责。

**自检页**：`static/_dev_uav.html` —— 单机特写转台（4 个视角 + 动画），可切 `?phase=SURVEY`、

**实现要求**

A. **任务流向箭头（task flow arrows）**——必须一眼看出"业务在往哪流、流多快"：
   * 上行数据流：每个 `busy` 无人机 → 地面站天线，沿**二次贝塞尔弧**（向上拱起，避免穿地形）
     流动的箭头串；箭头用 `InstancedMesh`（小三角锥/箭羽几何），数量 ∝ 任务进度与数量，
     
     移动速度 ∝ 上传速率（可用 `progress` 变化或固定 0.6~1.4 倍频），颜色按优先级
     （HIGH `#4ea1ff` / LOW `#f5a623`）；
   * 下行调度指令：地面站 → 无人机方向的**小一号青色**箭头（`#37e2d5`），只在有任务被调度时可见；
   * **弱网可视化**：`health < 55` 的链路，箭头变稀、变短、带抖动（模拟重传/丢包）；
   * 上限 `maxArrows`，`live==null` 时全部隐藏；不得因 30 架机 × 多箭头拖垮帧率（InstancedMesh 一批 draw call）。
B. **队列三维瀑布图（3D queue waterfall）**——课程报告要放的"高级图"：
   * 悬浮在地面站后上方（Lead 会传 anchor 或用默认 `(0, 34, 30)`），由**时间轴 × 队列泳道 × 深度**
     构成的三维曲面：X=时间（最近 `waterfallSlots` 个采样点）、Z=两条泳道（高优蓝、低优琥珀，
     错开 ±1.8 单位）、Y=队列深度（`heightScale` 单位/个）；
   * 用 `BufferGeometry` 三角带 + 顶点色（半透明加色）绘制"流动的瀑布带"，最新数据在靠近地面站一端；
   * 叠加：网格基线、深度刻度（0/50/100 条）、时间刻度（每 10 s 一条）、"当前时刻"亮边；
     标题/泳道名用 `makeTextSprite`；
   * 空数据（未开始）时画空坐标系，不要报错；
   * 每帧只更新 position/color attribute（预分配 Float32Array，`needsUpdate=true`），**不重建 geometry**。
C. **可开关**：`setMode("flow"|"waterfall"|"all"|"off")`，Lead 在 UI 面板绑定按钮。
D. **视觉验收**：截图里能同时看到 (1) 多条蓝色/琥珀色箭头流从机群汇向地面站；
   (2) 一块悬浮的半透明三维"瀑布"，能读出高/低队列深度随时间起伏。

```js
  create(opts) -> handle|null,

```

**`apply(snapshot)` 的 snapshot 形态（后端契约 §4.6 保证）**

```js
{
  preset: "clear"|"rain"|"snow"|"dust",
  label: "晴朗 / 中雨 / 降雪 / 沙尘",
  intensity: 0.0~1.0,
  visibility_km: 8.0,       // 能见度
  link_penalty: 0.0,        // 对链路健康度的平均扣分（前端只用于文案）
  wind_dir_deg: 0~360,
  wind_speed_mps: 0~20
}
```

**实现要求**

1. **粒子系统**（相机跟随体积，体积盒 90×50×90，中心 = 相机前方 30 单位处的投影点，避免"只见眼前一团"）：
   * 雨：`LineSegments`（每滴 2 个顶点沿速度方向拉长 0.8~2.2 单位），下落 + 风向倾斜，
     速度 28~40 单位/s，加色混合，`opacity ∝ intensity`；
   * 雪：`Points` + canvas 径向渐变圆点贴图，下落 2~5 单位/s + 正弦横向摆动 + 大小随距离衰减；
   * 沙尘：`Points`（土黄 `#c8a06a`，比雪大）+ 2~3 层半透明"沙墙"大面片（程序化噪声贴图，
     加色/透明混合，缓慢横向滚动），表现能见度骤降；
   * 全部在 `update(dt)` 里只改 attribute/材质 uniform，**不重建几何**；`clear` 时整体 `visible=false`。
2. **能见度衰减（重点：和链路健康度联动）**：
   * `apply()` 里由 `visibility_km` 反算 `scene.fog` 密度：项目世界尺度 176 世界单位 ≈ 7.3 km
     （DEM bbox，1 单位 ≈ 41 m），`FogExp2.density = k / max(0.8, visibility_world_units)`，
     clear 时恢复为现有的 `0.0034`；
   * 同时按预设调 `scene.fog.color`（雨 `#2a3340`、雪 `#cfd8e2`、沙尘 `#8a6a48`、晴=当前 TOD 雾色），
     `sun.intensity *= (1 - 0.55*intensity)`，`hemi.intensity *= (1 - 0.35*intensity)`；
   * `setTod(tod)` 由 Lead 在切时段时调用（保存 `todFogColor/sunIntensity/exposure` 作为基准），
     天气在其上做叠加，**切时段后天气效果不能丢**。
3. **性能**：cpu 档粒子 ≤1200 且不画沙墙；`update()` ≪ 1 ms；`stats.particles` 如实上报。
4. **视觉验收**：雨/雪/沙尘三张截图的画面基调、能见度、粒子方向明显不同；
   沙尘时远景山脊应几乎看不见（能见度衰减生效），而晴天下与升级前一模一样。
5. **不接管 DOM**：天气名/能见度/链路扣分的文字由 Lead 写在 HTML 面板里；模块只暴露 `current`。

### 4.6 后端：`src/uav_sim/weather.py` + 联动（Python 侧）

**目标**：天气不是"贴图滤镜"，而是**真的改链路健康度**，从而进入调度权重 → 生成可写进课程报告的对照数据。

#### 4.6.1 新增 `src/uav_sim/weather.py`

```python
WEATHER_PRESETS: dict[str, WeatherPreset]   # 至少 clear / rain / snow / dust
#   WeatherPreset: preset, label, visibility_km, link_penalty_max, intensity,
#                  wind_speed_mps, wind_dir_deg, fog_color_hex

@dataclass
class WeatherSample:
    ts: float
    preset: str
    intensity: float          # 0~1
    visibility_km: float
    link_penalty: float       # 对健康度的扣分（0~link_penalty_max）
    wind_speed_mps: float
    def to_dict(self) -> dict

class WeatherModel:
    def __init__(self, seed:int, preset:str="clear", duration_s:float=90.0, cfg:dict|None=None)
    def at(self, t:float) -> WeatherSample          # 0.5s 网格线性插值；确定性
    def apply_health(self, base_health:float, sample:WeatherSample) -> float
        # clamp(base_health - sample.link_penalty, 1.0, 100.0)
    def samples(self) -> list[WeatherSample]        # 已采样的（0.5s 一个）
    def set_preset(self, preset:str) -> None        # 运行中切换（确定性：只影响 t>=now 的曲线？见下）
    def mean_penalty(self) -> float
    def snapshot(self, t:float) -> dict             # /api/state 的 weather 字段（见 4.6.4）
```

**确定性 & 控制变量（硬要求）**
* 同 `(seed, preset, duration)` 任意次运行，`WeatherSample` 序列**逐点相同**；
* 5 种调度策略回放**同一条**天气曲线（与现有 LinkMonitor 的设计一致），保证对照实验只有调度策略一个变量；
* `preset="clear"` 时 `link_penalty` 恒 0.0 → 现有 15 组实验结果**逐位不变**（回归测试必须验证这一条）；
* 曲线形态：onset（0→peak，约 8~15%）→ 平台期带阵风抖动（±15%）→ 尾部衰减；强度曲线由
  `random.Random(seed * 7919 + hash(preset) % 100003)` 生成，**不要用全局 random**。

**配置项（写入 `config.yaml`，新 `weather:` 段，旧配置缺省时用代码默认值）**

```yaml
weather:
  default_preset: clear        # clear/rain/snow/dust —— 默认必须 clear（保结果不变）
  enable_dynamic: true         # 是否有 onset/阵风/衰减，false=恒定强度
  grid_s: 0.5                  # 天气曲线网格（与 link_monitor.HEALTH_GRID_S 对齐）
  presets:
    clear: { visibility_km: 12.0, link_penalty_max: 0.0,  wind_speed_mps: 1.5 }
    rain:  { visibility_km: 3.0,  link_penalty_max: 18.0, wind_speed_mps: 8.0 }
    snow:  { visibility_km: 1.2,  link_penalty_max: 24.0, wind_speed_mps: 4.0 }
    dust:  { visibility_km: 0.6,  link_penalty_max: 32.0, wind_speed_mps: 14.0 }
```

#### 4.6.2 改 `src/uav_sim/link_monitor.py`

* `LinkMonitor.__init__(..., weather: WeatherModel | None = None)`（**新增可选参数，默认 None**）；
* `_build_series()` 里生成完基础健康度后，按网格时刻 i*0.5 取 `weather.at(t)` 应用
  `h = weather.apply_health(h, sample)`（**必须在种子噪声之后**，保证物理意义：天气是外部衰减）；

* `mean_health()` 等原有方法行为不变；`weather=None` 时数值与改动前**逐位相同**。

#### 4.6.3 改 `src/uav_sim/simulator.py` / `experiment.py`
