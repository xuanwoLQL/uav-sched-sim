## 2. 渲染管线

### 2.1 SSAO 在 EffectComposer 中的位置

```
RenderPass(主场景)
   ↓ readBuffer = 已着色画面
SSAOPass        ← 新增（index=1）
   ├─ ① 一次预渲染：scene.overrideMaterial = MeshNormalMaterial → 内部 RT
   │     （同一 RT 挂 DepthTexture，省掉一次深度 pass）
   ├─ ② AO：半分辨率，16~18 个半球核样本 + per-pixel 随机旋转，
   │     由深度反投影视空间位置、由法线 RT 取视空间法线，深度比较估遮蔽
   ├─ ③ 双边模糊：去采样噪点，半径随深度自适应
   └─ ④ 合成：outColor = beauty * mix(1.0, ao, strength)
   ↓
UnrealBloomPass → 屏幕
```

**为什么这么设计（可直接写进报告）**
* **AO 必须在泛光之前**：先做接触阴影再做泛光，暗部不会被泛光"洗掉"，台阶/树根/机身下方的接触阴影才能保留；
* **一次预渲染拿法线+深度**：`MeshNormalMaterial` 覆盖材质只渲一遍，比 examples 里"beauty+depth+normal"三次渲染省 2/3 的开销；
* **半分辨率 + 双边模糊**：SSAO 是低频信号，半分辨率肉眼几乎无差，开销降到 1/4；
* **深度=远平面跳过**：天空球/远景不参与遮蔽估计，避免"天国黑斑"这种最典型的 SSAO 事故。

**质量参数（主页面 `initUpgradeModules()` 传入）**
`strength 0.92 / radius 0.55 / samples 18（LITE 档 8）/ halfRes true / blur true / bias 0.02 / maxViewZ 460`；
CPU 软件光栅档 `capable()` 直接返回 false，SSAO 自动不装。

### 2.2 地形 LOD（几何 clipmap + 纹理 clipmap）

* **几何 clipmap**：以相机 XZ 为中心的 4 级同心环带，顶点间距 `s, 2s, 4s, 8s`（`s` = DEM 格距 = `max(W/(N-1), D/(M-1))`）；
  第 k 级只画 `S(k) − S(k−1)` 的 L 形环带，外环覆盖整个世界矩形（含 1.5% 外扩）。
  * 环中心吸附到上级网格整数倍 → 相机移动时顶点"跳格"而非连续滑动，消除 clipmap 典型的顶点游动/闪烁；
  * 环边界处外环按内环细间距细分（共用同一批世界坐标 + 同一 `heightAt`），再补一圈向下裙边，**陡坡 T 型接缝也不会露缝**；
  * 相机移动超过「间距/2」才重定位对应环，不是每帧重建几何。
* **纹理 clipmap（v1.2 改法）**：模块内 canvas 程序化生成岩石/土壤细节纹理，**全环 + 外延带共用同一个世界对齐 `tileWorld=6`**：
  UV 直接烘成世界坐标（`uv = worldXZ / 6`）→ 环与环之间纹理连续，俯视/远景不再出现"每环不同密度的矩形拼缝"；
  细节纹理改"近白微对比"（均值 0.972 / 范围 0.95~0.99，sRGBEncoding），宏观起伏交给顶点色里的**世界坐标低频噪声**（±10%，两尺度 ~70 / ~26 世界单位）；
  保留原 `vertexColors` 坡度-高程配色（ROCK/SOIL/DEEP + 曲率 AO）；原「动态云影」shader 注入到每环材质（`materials[]` 暴露给主页面）。
* **多角度清晰度（v1.2）**：法线统一按 DEM 格距差分（各环共享同一套细节法线，粗环远景不再糊、环边界无明暗跳变）；
  顶点色函数改低频（坡度差分 3 格距、AO 半径 ~5 世界单位、高程明暗带周期 ~24）→ 稀疏粗环不再出矩形亮度斑块；
  相机高度 > 90 时整体细分一档（`baseSpacing 0.344 → 0.172`，缓存点阵不变），保证俯视/远景屏幕误差不爆炸。
* **为更大 DEM 铺路（已落地）**：所有尺寸由 `field.N/M` + `world` 推导、无硬编码；2026-11 已把 DEM 换成 **1024×760 / 14.6×10.8 km**、世界 **352×256**，
  `_dev_terrain.html?nx=1024&nz=768` 压力测试下三角形数不随 DEM 分辨率线性爆炸。
* **外延缓冲带（apron）**：世界矩形外再铺一圈低模"大地"（7,552 tris / 1 draw call），边缘平滑下压到大地基底并入雾，消除"悬空岛/断崖"。
* **预算**：high ≤ 260k tris、medium ≤ 120k、cpu ≤ 40k；主页面实测 high 档 87k（iso/far）~190k（俯视）tris、drawCalls ≤ 6。

### 2.3 无人机模型细化

| 可动件 | 实现 | 关键细节 |
|---|---|---|
| 桨叶运动模糊 | 每旋翼 2 片"根宽尖窄"薄桨 + 1 片加色模糊盘 | 盘不透明度随转速 0.06→0.44(巡航)→0.62(满载)，桨叶透明度 0.90→0.25 交叉淡出；盘内用扫掠瓣的"曝光积分"呈现隐约桨影，而不是实心圆片 |
| 云台跟随 | yaw→pitch 二轴 Group + 相机机身/发光镜头 | 阻尼 lerp + 角速度限幅 2.1 rad/s + ±0.5° 稳像抖动；pitch 限幅 [−85°, +20°]；PAD 回正、SURVEY 俯视扫描点，实测指向误差 Δyaw 0.14°/Δpitch 0.06° |
| 起落架收放 | 前/后 2 个铰链 Group（各 2 腿 + 滑橇） | 按架次状态 PAD/LAND 放下、CLIMB 离地后 0.35s smoothstep 收起；只转腿、机身高度不动 |

性能：high 档 17 mesh / 1472 tri 每架，cpu 档 10 mesh / 984 tri；几何与材质按档位模块级缓存共享，每架仅 4 个"会变色"的独立材质；
30 架 = 482 draw calls / 43k tri，`anim()` 30 架合计 **0.16~0.18 ms/帧**（零分配）。

## 3. HUD 数据可视化

### 3.1 任务流向箭头（把"业务在往哪流"画出来）

* 每条 busy 链路 = 一条二次贝塞尔弧（控制点抬高，避免穿地形/穿山），弧上流动一串小棱锥箭头；
* **全部塞进 1 个 `InstancedMesh`**（1 次 draw call），颜色用 `instanceColor`：高优 `#4ea1ff` 蓝、低优 `#f5a623` 琥珀、下行调度指令 `#37e2d5` 青（反向小号）；
* 移动速度 ∝ 上传速率；**弱网可视化**：`health < 55` 的链路箭头变稀、变短、带抖动 —— 对应真实数传丢包/重传；
* 数据源：`/api/state` 的 `live.running_tasks`（uav_id/priority/progress）+ `live.uav_states[].health`；`live==null` 时全部隐藏。

### 3.2 队列三维瀑布图（报告里的"高级图"）

* 悬浮在地面站右后上方 `anchor ≈ (46, 26, 34)`：**X = 时间**（最近 90 个采样 = 45 仿真秒）、**Z = 两条泳道**（高优蓝/低优琥珀，错开 ±4 世界单位）、**Y = 队列深度**（0.13 世界单位/条）；
* 三角带 + 顶点色的半透明加色"帘幕"，顶部亮、底部透明；叠加网格基线、深度刻度 0/100、时间刻度每 10s、"当前时刻"亮边；
* **深度上限压平**：PEAK 工况低优队列可达 1200+，可视化用 `WF_DEPTH_MAX=140` 压平（不压平会变成一堵几百米高的白墙，把画面顶穿）；
* 每帧只更新预分配 `Float32Array` 的 position/color，不重建 geometry（零分配）。

## 4. 天气系统（本次升级的"弱网论证"核心）

### 4.1 视觉层（`weather_system.js`）

| 工况 | 粒子 | 能见度（满强度） | 世界单位 | `FogExp2.density` | 60 单位处雾权重 |
|---|---|---|---|---|---|
| clear 晴朗 | 无 | 12.0 km | 292.7 | 0.00160（2026-11 远景清晰度调整值） | 2% |
| rain 中雨 | 2550 条倾斜雨丝（LineSegments） | 3.0 km | 73.2 | 0.01708 | 65% |
| snow 降雪 | 2720 个柔边白点（Points） | 1.2 km | 29.3 | 0.04271 | 99.9% |
| dust 沙尘 | 2040 个土黄颗粒 + 3 层滚动沙墙 | 0.6 km | 14.6 | 0.08542 | 100% |

映射公式：`density = K / max(0.8, visibility_world)`，`K=1.25`，`visibility_world = visibility_km×1000/41`（项目世界 352 单位 ≈ 14.6 km，1 单位 ≈ 41 m；倍率不变，所以能见度→雾密度的物理映射仍然成立）；
clear 恢复为项目基准雾密度 `0.0016`（2026-11 从 0.0034 下调：世界放大后远景 300+ 单位都在雾里，会"一换视角就糊"）。
同时按强度衰减光照：`sun = todSun×(1−0.55i)`、`hemi = todHemi×(1−0.35i)`，雾色按预设（雨 `#2a3340` / 雪 `#cfd8e2` / 尘 `#8a6a48` / 晴 = 当前时段雾色）；
`setTod()` 保存"时段基准"，天气在其上叠加 —— 切"黎明/正午/黄昏/夜景"不会把天气效果冲掉。

### 4.2 数据层（`weather.py` + `link_monitor` 联动）

**链路：天气 → 链路健康度 → 动态权重 → 指标**

```
WeatherModel（0.5s 网格，确定性：onset 爬升 → AR(1) 阵风 ±15% → 尾部衰减）
   → WeatherSample(ts, preset, intensity, visibility_km, link_penalty, wind_*)
   → LinkMonitor._build_series()：在"种子噪声之后"施加  h = clamp(h − link_penalty, 1, 100)
   → health_at(uav, t) → 任务失败概率 p_fail=(1−h/100)×retry_gain
   → 动态权重 W 的链路因子 L（弱网降权）+ 弱网阈值 cache_health_threshold=40（进入本地缓存）
```

**确定性保证（控制变量的关键）**：同 `(seed, preset, duration)` 的天气序列逐点相同；5 种调度策略回放**同一条**天气曲线；
`clear` 时 `link_penalty ≡ 0`，且与改动前实现做了 16740 点逐点浮点对拍，**默认工况数据零影响**。

**API / 交互**
* `GET /api/weather?preset=clear|rain|snow|dust`：运行中立即重建链路健康度曲线（秒级生效），未运行则作为下次启动默认值；非法 preset 返回 400 JSON。
* `/api/state` 顶层 `weather` 字段（preset/label/intensity/visibility_km/link_penalty/available）；运行中为实时值，空闲/刚结束为平台期典型值。
* 主页面右下"渲染增强 · 天气与模块"面板：晴/雨/雪/沙尘四个按钮直接调上述 API；三行读数"天气 / 能见度 / 链路衰减"与 3D 天气效果来自**同一份数据**。

### 4.3 天气对照实验（`python run.py weather`）

* 固定 PEAK 工况，4 种天气 × 5 种调度策略 = 20 组，产出
  `results/weather_matrix.csv`（21 列，含链路确定性列 + 业务指标列）与
  `charts/08-天气-链路健康度与指标联动.png`。

**链路结论（确定性，可直接引用）**

| 天气 | 链路健康度均值 | 劣质链路占比（health<45） |
|---|---|---|
| 晴朗 | 42.78 | 54.0% |
| 中雨 | 30.66 | 84.1% |
| 降雪 | 24.10 | 92.4% |
| 沙尘 | **18.02** | **94.4%** |

沙尘 vs 晴朗：健康度均值 42.78 → 18.02（**−24.76**），劣质链路占比 54.0% → 94.4%（**+40.4 pp**）。

**业务结论（同批次单次实跑，沙尘工况）**：dynamic 完成率 92.3% vs 静态优先级 31.3%（**+61.0 pp**）；
高优平均等待 dynamic 36367 ms vs priority 28507 ms；低优饥饿率 dynamic 0.0% vs priority 52.6%。

> ⚠️ **引用口径（报告务必保留）**：链路两列（健康度均值/劣质占比）是**确定性结论**，可放心引用；
> 完成率/等待/饥饿率是**单次实跑**。本仿真器用真实墙钟模拟 IO/调度，机器负载高时同参数复跑可差数十个百分点
> （实测安静时段 <1 pp、满载时段可达数十 pp）。**报告只做同一张表内横向比较，不要跨批次/跨机器比较。**

## 7. 课程报告可直接引用的 4 段结论

1. **渲染层面**：把"顶点烘焙 AO"升级为屏幕空间 SSAO 后，采坑台阶下沿、树根、机身下方出现随距离变化的接触阴影；
   地形由"整张 21.4 万面固定网格"改为相机中心 4 级 clipmap，屏幕三角形数与 DEM 分辨率解耦，为更大范围 DEM 铺路。
2. **可视化层面**：任务流向箭头把"哪架机在传、传得多快、链路好坏"变成一眼可读的 3D 动画；队列三维瀑布图把
   高/低优先级队列深度的时间演化搬进 3D 场景，直观展示 dynamic 策略对低优队列的压制与补偿。
3. **天气与弱网**：天气不是贴图滤镜，而是通过"能见度 → 链路扣分 → 任务失败概率 → 动态权重"真正进入调度闭环；
   沙尘工况下链路健康度均值从 42.78 降到 18.02、劣质链路占比从 54.0% 升到 94.4%（确定性结论）。
4. **策略对比**：同一沙尘批次内，动态权重策略完成率 92.3% 显著高于静态优先级 31.3%，低优饥饿率 0.0% vs 52.6%，
   说明"链路感知 + 饥饿补偿 + 限流稳流"在恶劣工况下依然维持业务连续性 —— 这就是"弱网自适应调度"的量化证据。
